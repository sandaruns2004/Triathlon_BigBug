WAYPOINT FLOW — GOOGLE STITCH MOBILE UI PROMPTS

Use these as separate prompts in Google Stitch. Build high-fidelity Android/iOS-neutral mobile app screens at 390 px wide. Keep the interface clean, practical, and ready for a logistics operations product—not a generic consumer shopping app. Use Inter or a similar modern sans-serif; 16 px minimum body text; 48 px minimum tap targets; accessible labels for all icons. The shared visual system is: dominant white background, deep forest green #146B45, primary action green #1F8A5B, pale green #EAF6EF, dark text #17221D, soft grey #DCE5DF borders, 12 px rounded cards, restrained shadows. Use amber for warnings and red only for failed/blocked work. Show realistic Sri Lankan delivery data and use the product name “Waypoint Flow”.

PROMPT 1 — MOBILE DESIGN SYSTEM AND APP FOUNDATIONS

Create a high-fidelity mobile design-system reference and app-shell examples for “Waypoint Flow”, a connected delivery-planning product for Sri Lankan retail operations. It serves two mobile roles: drivers in the field and store managers at retail outlets. The interface must be clean, white-and-green, practical in bright outdoor conditions, and never resemble a generic shopping app.

Build a compact visual style guide with the palette: white #FFFFFF dominant surface, deep forest green #146B45 for brand/navigation, action green #1F8A5B for primary actions, pale green #EAF6EF for supportive surfaces, ink #17221D for text, and border grey #DCE5DF. Use amber for warnings and red only for blocked/failed work. Use Inter or a similar sans-serif, 16 px minimum body text, 48 px minimum tap targets, visible focus/selected states, labelled icons, 12 px rounded cards, and restrained shadows. Show status-chip components: Needs planning, Planned, Loading, Ready to depart, On route, Delivered, Issue reported, Deferred, plus Offline and Synced states.

Show two app-shell examples at 390 px width: a Driver shell with bottom navigation Today, Route, Activity, Profile and a persistent current-delivery task area; and a Store Manager shell with Home, Orders, Notifications, Profile. Include compact components for a primary button, secondary button, text button, list row, timeline event, offline banner, connection pill, form field, and bottom sheet. State that route guidance and proof capture happen only while safely parked; offline records must say “Saved on this phone” versus “Synced”. Make this an elegant, implementation-ready mobile foundation page.

PROMPT 4 — DRIVER PROOF OF DELIVERY

Design a high-fidelity 3-step mobile proof-of-delivery flow for Waypoint Flow. It is used by a driver only when safely parked, and it must work as an interruption-friendly, offline-capable logistics workflow. Use white surfaces, deep green #146B45, action green #1F8A5B, pale green #EAF6EF, dark text, subtle grey borders, large 48 px controls, and an operational—not consumer—tone.

Add an offline state at the bottom: “Saved on this phone — will sync when online”, not a misleading success message. Use a realistic delivery product visual hierarchy and ensure the output feels buildable.

PROMPT 5 — DRIVER OFFLINE AND SYNC CENTRE

Design a high-fidelity mobile offline-and-sync centre for the Waypoint Flow driver app. The scenario is that connectivity dropped while making deliveries, but route and proof records must continue safely. The design should feel reassuring and transparent, not alarming. Use a white-first interface, forest green #146B45, action green #1F8A5B, pale green #EAF6EF, amber for connectivity attention, near-black text, subtle grey borders, 12 px rounded cards, and accessible large controls.

At the top show page title “Sync centre” and an amber persistent banner: “You’re offline. Your route and delivery records are available on this phone.” Below it show small status details: “4 actions queued” and “Last synced 07:42 AM”. Create a status card with an offline icon, “Records are encrypted and saved on this phone”, and a disabled-looking “Sync now” button with helper text “Available when connected”.

Add a “Queued actions” list of realistic rows: “Waypoint Fresh — Borella · Proof of delivery · 08:04 AM · 2 photos”, “Waypoint Style — Rajagiriya · Delivery completed · 08:29 AM”, “Waypoint Tech — Nugegoda · Access issue · 08:41 AM”. Each has a clear “Saved on this phone” label. Include a conflict card for a route/order update received later: “Route changed while you were offline”; show old vs new stop information, preserve both records, and provide “Review difference” plus “Contact operations”, never a silent overwrite. At the bottom, show a compact successful reconnection state card as an alternate component: green check, “4 records synced”, and “View activity”. Include bottom navigation with Activity active. Make the hierarchy and error recovery easy to understand at a glance.

Design a polished, high-fidelity mobile authentication set for Waypoint Flow, a secure delivery operations app used by drivers and store managers. Use a clean white interface with a small pale-green route-line accent, Waypoint Flow logo near the top, deep forest green #146B45, action green #1F8A5B, pale green #EAF6EF, dark text, subtle grey borders, 48 px inputs/buttons, and accessible visible labels. Create four related screens. Screen 1 “Welcome to Waypoint Flow” sign-in: email and password fields, show/hide password control, full-width green “Sign in” button, “Forgot password?” and “Activate account” links, plus an optional outlined “Continue with Waypoint SSO” button. Add small shared-device guidance and a neutral support link. Screen 2 “Activate your account”: explain that setup begins from a Waypoint invitation, show masked email “ni•••@waypoint.lk”, invitation-validity card, password and confirm-password fields with clear requirements, then read-only profile context such as “Assigned outlet: Waypoint Fresh — Borella”; use a green “Activate account” button.
